# 需求意图延续合同

## 1. 问题

视频需求不是一句“生成视频”，而是一组在多个模型和工具之间传递的约束：

- 人物是谁，哪些镜头出镜；
- 同一人物穿哪套服装，使用哪个定妆版本；
- 商品是什么，哪些外观和卖点已核实；
- 速度、动作、运镜和节奏要达到什么观感；
- 原声、口播、配乐、字幕、文字层如何处理；
- 平台、画幅、分辨率、帧率和时长是什么；
- 哪些动作、人物、服装、商品和声音必须跨镜连续。

这些约束可能依次经过路由、需求洞察、SceneArchitect、PRD、PromptFusion、关键帧、供应商视频、正式后期和交付。任何一层只看到“通用默认”，都可能把客户原意改成更容易执行的平均值。赛车“看起来像巡航”就是运动约束在后续流转中丢失后的表现；同类问题也可能表现为换装、换脸、换商品、补错声音或字幕策略改变。

## 2. 单一权威

`workloom.production-intent-contract/v1` 在模型改写前从以下来源冻结：

- `customerOriginalIntent`；
- 完整客户 Brief；
- 片级客户字段（标题、平台、时长、要求等）。

生成后的镜头卡、模型摘要和历史成功产物不参与权威来源提取，避免模型输出自我认证。

每条硬约束包含：

```json
{
  "id": "PI-MOTION-7ab79f06ce",
  "category": "motion",
  "statement": "客户原始条款",
  "sourcePath": "brief/style/primary",
  "sourceSha256": "<完整来源文本摘要>",
  "enforcement": "hard"
}
```

合同同时记录全部来源摘要、来源根摘要、运动意图和 `contractSha256`。完整文件写入 `<workDir>/intent-continuity-<projectId>.json`。

## 3. 分类

当前可机检分类为：

- `motion`
- `identity`
- `wardrobe`
- `product`
- `audio`
- `text`
- `platform`
- `duration`
- `continuity`
- `other`

分类不是新的创作来源，只用于把同一份客户原文绑定到不同执行门。

## 4. 各阶段消费

| 阶段 | 消费方式 | 失败条件 |
|---|---|---|
| SceneArchitect | 在原生场景提示中附完整合同；要求 `productionContract.actions` 落实动作与速度意图 | 合同丢失、字段边界改变、无法取得真实结构 |
| PRD | 在 G4 后的私有权威输入中附分类合同，邻近完整 Brief | 模型无法取得同一合同或把模板优先于客户约束 |
| PromptFusion | 最终提示词附紧凑合同块，列出全部适用分类和条款 ID | 提示词预算无法容纳时不截断，直接失败 |
| G6 | 审核最终提示词并把合同摘要写入门证据 | 缺合同、遗漏条款 ID、未通过审核 |
| G7 | 逐镜核对最终提示词仍绑定同一合同 | 缺镜、提示词变化、只留旧通过记录 |
| G8 | 付费 POST 前再核对合同、速度和引用锚点 | 任意适用条款丢失或正面表达与速度意图冲突 |
| 后期/交付 | 运动分类决定速度坡道和插帧；交付清单写合同摘要 | 无合同回执、实际加工失败、技术验收失败 |

最终提示词仍受原生 PromptDeliveryGuard 的 3000 字硬上限。紧凑块只压缩执行表达，不删条款 ID；完整原文由同轮 Brief 和合同文件保留。超出预算时 fail-closed，不能静默截去客户要求。

## 5. 运动意图

运动合同从客户原文中的能量、动作、追车、竞速、加速和节奏词提取，得到：

- `high-energy-action`
- `dynamic`
- `steady`
- `unspecified`

高燃动作项目中的动作镜可使用速度坡道；对白镜不加速口播。合成时 `--frame-interp auto` 对低帧率动作源使用运动补偿插帧。

成片 `G-INT1` 使用帧差筛查找回“速度长期过稳/没有坡道”的明显回归。该信号不能证明：

- 真实车速；
- 物理合理；
- 动作先后正确；
- 艺术效果合格。

因此 G-INT1 与场景/动作合同、实体常识审核和人工首中尾画面复核并存。

## 6. 扩展新意图

新增一种意图时按以下顺序实现：

1. 在合同中新增分类或结构化字段；
2. 为提取规则增加正反例测试；
3. 定义每个阶段如何消费；
4. 定义可验证的提交前、生成后或交付门；
5. 将证据写入阶段账本与交付清单；
6. 更新固定工作台指南和回归。

不能只在某一个 prompt 里加一句“注意某某”，也不能把当前项目的具体人物、商品、故事或秒数写进通用代码。
